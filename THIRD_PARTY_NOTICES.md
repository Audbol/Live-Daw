### libwing parameter data

- Project: libwing, <https://github.com/jerrythemaus/libwing> (a fork of
  <https://github.com/dannydulai/libwing>), revision
  `410cc1596384ea02d2fef9393c4da2bce59d9ad7`
- Licence: **Apache License 2.0**, [licenses/Apache-2.0.txt](licenses/Apache-2.0.txt)
  (the licence file of that repository, copied verbatim; libwing ships no NOTICE
  file and names no copyright holder in it. Its `Cargo.toml` declares `license =
  "MIT"`; Sidecar follows the Apache-2.0 licence file.)
- Used for: Sidecar does not include libwing's code. Two files are generated from
  libwing's WING parameter sweep (`propmap.jsonl`, firmware 3.1):
  - `rust/crates/livedaw-wing/data/wing_tree.bin`, the WING parameter tree (node
    names, ids, types, units, ranges and choices), generated by
    `tools/wing/gen_tree.py` and compiled into the application;
  - `rust/crates/livedaw-dsp/src/wing/models_gen.rs`, the processing models'
    parameter names, ranges and choices, generated by `tools/wing/gen_models.py`
    (the defaults in it are the console's, captured from WING Edit's snapshots into
    `tools/wing/model_defaults.json`; they are facts about the console's settings).

  Both files are modified, re-encoded extracts of libwing's data: only metadata is
  taken, re-arranged into Sidecar's own formats.
- Development only (not distributed): `tools/wing/libwing_tools.sh` clones libwing to
  build its command-line clients for testing Sidecar's WING remote servers;
  `tools/wing/oscprobe.rs` is Sidecar's own code built against libwing there.
