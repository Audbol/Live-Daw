# WING vs Sidecar: audio test plan

Generated by `plan.py` (edit that file, then run `python3 plan.py`); the same plan is in
`test_plan.json` for the scripts. Every test sets **channel 1** (and for FX tests FX slot 1),
plays its signal file from the WING's USB player into channel 1, and records Main 1 L/R plus
the raw player signal with the WING's USB recorder. Sidecar's side is rendered offline from
the same settings (`run_all.py`), so at the console you only record the WING.

## Time

| Stop after | Tests | Dialling by hand | With `wing_osc.py apply` |
|---|---|---|---|
| priority 1 | 28 | about 83 min | about 24 min |
| priority 2 | 58 | about 171 min | about 51 min |
| priority 3 | 68 | about 201 min | about 59 min |

Priority 1 is the baseline, the WING EQ, the filters, the WING COMP and the WING GATE; stop
whenever you like, every finished test is useful on its own. By hand counts about 2.5 minutes per
test for setting up and starting/stopping the recorder; with the OSC helper about 25 seconds.

## Before the first test (once)

1. **Save your show** on the WING (LIBRARY), then start from a clean console: SETUP > INITIALIZE
   CONSOLE (or at least: every other channel, aux and bus off Main 1, Main 1 processing off).
2. Copy the folder `signals/tests` from `make_signals.py` to a USB stick (FAT32 or exFAT) and plug
   it into the WING's USB port (the one for the USB recorder / player).
3. Patch (ROUTING), or let `python3 wing_osc.py WING_IP setup` do it:

| Path | Value | On the console |
|---|---|---|
| `/ch/1/in/conn/grp` | PLAY | CH 1 > INPUT > CHANNEL INPUT MAIN: source group |
| `/ch/1/in/conn/in` | 1 | CH 1 > INPUT > CHANNEL INPUT MAIN: input number |
| `/io/in/PLAY/1/mode` | M | ROUTING > SOURCES > group USB PLAYER > 1 > MODE |
| `/io/in/PLAY/1/mute` | 0 | ROUTING > SOURCES > group USB PLAYER > 1 > MUTE |
| `/io/in/PLAY/1/pol` | 0 | ROUTING > SOURCES > group USB PLAYER > 1 > POL |
| `/io/out/REC/1/grp` | MAIN | ROUTING > OUTPUTS > output group USB REC (RECORDER) > 1: source group |
| `/io/out/REC/1/in` | 1 | ROUTING > OUTPUTS > output group USB REC (RECORDER) > 1: source number |
| `/io/out/REC/2/grp` | MAIN | ROUTING > OUTPUTS > output group USB REC (RECORDER) > 2: source group |
| `/io/out/REC/2/in` | 2 | ROUTING > OUTPUTS > output group USB REC (RECORDER) > 2: source number |
| `/io/out/REC/3/grp` | PLAY | ROUTING > OUTPUTS > output group USB REC (RECORDER) > 3: source group |
| `/io/out/REC/3/in` | 1 | ROUTING > OUTPUTS > output group USB REC (RECORDER) > 3: source number |
| `/io/out/REC/4/grp` | OFF | ROUTING > OUTPUTS > output group USB REC (RECORDER) > 4: source group |
| `/rec/channels` | 4 | USB RECORDER > 2-CH / 4-CH |
| `/rec/resolution` | 24 | USB RECORDER > 16 / 24 bit |

That is: channel 1's MAIN input = USB PLAYER 1, a mono source (MODE M: if PLAYER 1/2 were a
stereo pair, channel 1 would become a stereo channel); recorder inputs 1-2 = MAIN 1 L / R, 3 = USB
PLAYER 1 (the unprocessed signal: it lets the analysis measure latency and correct any level
offset of the player or recorder), 4 off. USB RECORDER set to 4-CH, 24 bit, WAV. The files are
mono; should the player not take mono files, write stereo ones (`make_signals.py --stereo`, the
same signal on both sides).
4. **Levels:** nothing to adjust. The player has no gain, the channel's TRIM is 0 dB, fader and Main
   1 at 0 dB; the files peak at -6 dBFS (the level steps of the dynamics tests reach 0 dBFS), so
   nothing clips. Do not touch the input gain, fader or Main fader during the session.
5. Settings every test starts from (the helper sets them with each test; by hand: set them once,

## For each test

1. Set the test's settings (by hand from the table, or `python3 wing_osc.py WING_IP apply NAME`, which
   also reads every value back and saves what the console reports).
2. USB RECORDER: REC. USB PLAYER: play the test's file (`signals/tests/NN_name.wav`).
3. When the player stops (a falling chirp ends every file), STOP the recorder.
4. Note nothing: the recording carries the test's ID code. Name it after the test if you like
   (`eq_peq_600_p6_q1.wav`); `run_all.py` finds the test either way.

Values are as the console shows them; the console puts a value on its own steps (600 Hz reads
601.4), and Sidecar's render does the same, so set the closest value the knob gives.
Sidecar reads the very same paths: the render tool (`render --settings`) applies them through
Sidecar's WING mapping, so `/ch/1/eq/2g` is EQ band 2's gain on both.
